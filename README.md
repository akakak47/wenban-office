# 文伴 WENBAN · 批量文档工作台

一个免费的浏览器文档工具：把 Excel 名单或粘贴的数据填入 Word 模板，批量制作奖状、会议桌签和其他重复文档，也能将一列姓名排列为多行多列表格。

无需注册、后端服务器、数据库或 API Key。文件解析、模板填充和结果打包都在当前浏览器中完成。

源码仓库：[akakak47/wenban-office](https://github.com/akakak47/wenban-office)。已通过 GitHub Actions 完成 GitHub Pages 部署，后续推送到 `main` 会自动重新构建、测试并发布。

## 功能概览

| 工具 | 输入 | 输出 |
| --- | --- | --- |
| 批量奖状 | Excel 名单或一列姓名；内置/自定义 Word 模板 | 合并 DOCX 或每人一份 DOCX 的 ZIP |
| 会议姓名牌 | 参会名单；内置对折样式/自定义模板 | 每人一页 A4 的对折桌签，或按自定义模板输出 |
| 名单转表格 | 粘贴一列姓名 | 可复制的 TSV 表格及 XLSX 文件 |
| 通用模板填充 | 任意文本占位符 DOCX + 多列粘贴数据 | 批量填充后的独立 DOCX ZIP 或兼容模板的合并 DOCX |

## 使用方法

### 1. 批量奖状

1. 选择「批量奖状」，上传 `.xlsx`、`.xls` 或 `.csv` 名单，也可切换到粘贴文本。
2. 上传表格后确认工作表、表头所在行和姓名列。空姓名行自动跳过，重复姓名保留。
3. 使用内置奖状时，设置标题、奖项、颁发单位和日期。
4. 使用自定义 Word 时，把需要替换的文字改为单层花括号占位符，例如 `{姓名}`、`{奖项}`，保存为 `.docx` 后上传。
5. 为每个占位符选择对应的表格数据列，查看填充内容。
6. 选择合并 Word（方便一次打印）或独立文件 ZIP（方便逐人发送），生成并下载。

粘贴姓名模式只提供姓名数据；要同时匹配班级、奖项等字段，可上传 Excel，或使用「通用模板填充」。

### 2. 会议姓名牌

1. 导入参会名单。
2. 内置模板为 **A4 纵向、一人一页、上半页倒置、下半页正向**；上下两处使用同一姓名。
3. 根据需要调整字号、颜色和副标题。
4. 下载后在 Word/WPS 中选择 **A4、单面、实际大小** 打印，沿中间对折线折叠。

内置样式使用可编辑艺术字，字体为「华文行楷」。字体未安装时，Office 软件可能替换字体；不同软件的艺术字渲染也可能不同，请先试打一页。

**自定义桌签模板：**

- 将上下两处姓名都设置为 `{姓名}`，上传 `.docx` 并匹配数据列。
- 也可填写模板中原有的姓名，系统会把匹配的文字替换为姓名占位符；旋转艺术字同样支持。
- 网站可下载内置对折模板作为起点。
- 对于符合检测规则的单表格、多对重复桌签模板，仅使用第一对作为单人的模板；界面会提示。复杂版式建议先整理为一人的模板再上传。

### 3. 名单转表格

1. 粘贴一列姓名，每行一个，也可从 Excel 中直接复制。
2. 指定列数或行数，选择按行/按列排列。
3. 最后一行或一列不足时自动补空单元格。
4. 点击「复制表格」，在 Excel/WPS 中选定起始单元格后粘贴；也可下载 `.xlsx`。

此工具输出 TSV/XLSX，不直接生成 Word 表格。空行忽略，重复姓名默认保留，可勾选去重。浏览器拒绝剪贴板权限时，可在页面下方纯文本框中手动复制。

### 4. 通用模板填充

例如，要为每个人生成一份通知书，在 Word 中设置：

```text
姓名：{姓名}
学号：{学号}
联系方式：{联系方式}
```

1. 上传 `.docx`，系统自动识别字段并建立对应的信息列。
2. 每个输入框粘贴一列数据，不带表头；字段名称不需要花括号。
3. 可添加、删除或修改字段列；字段名称必须和模板占位符一致。
4. 各列第 1 行对应第 1 份文档，第 2 行对应第 2 份文档，以此类推。
5. 检查右侧数据对应表与逐条文本预览，再生成结果。

| 姓名列 | 学号列 | 联系方式列 |
| --- | --- | --- |
| 张三 | 001 | 13800000001 |
| 李四 | 002 | 13800000002 |

上述数据生成两份文档，同一占位符在模板内出现多次时会一起替换。

**数据规则：**

- 保留学号的前导零、电话号码、重复值以及中间空行。
- 末尾一个换行被视为复制粘贴的分隔符并忽略。
- 各列行数不同会阻止导出；可补齐，或明确勾选「缺失值留空」。
- 整行数据为空仍算一条记录，会生成一份空白填充文档。
- 缺少模板所需字段、字段名称重复或一个输入框粘贴了多列时，页面会提示。
- 更换模板时，同名字段的已填数据保留；新模板不使用的列不再保留。

## 模板规范与格式保留

- 只接受 `.docx`；旧版 `.doc` 请先用 Word/WPS 另存为 `.docx`。
- 使用普通文本占位符，如 `{姓名}`，不要使用双层 `{{姓名}}`。
- 字段名尽量使用简短中文、英文字母或数字，避免花括号及模板控制语法字符。
- 当前界面面向文本替换，不提供图片替换、条件表达式或循环表格编辑功能。
- 输出沿用原模板的字体、段落、表格、图片和页面设置，并非根据网页预览重新排版。
- 网页中的自定义模板预览仅为文字内容预览，不是 Word 的精确排版预览。
- 替换文字变长可能导致换行、单元格伸展或重新分页；最终效果以 Word/WPS 为准。
- 多节模板或包含页眉页脚变量的模板，使用独立 DOCX ZIP，避免合并影响内容与页面设置。
- 合并模式让每条记录另起一页，不等同于保证每条记录只能占一页。

## 限制与隐私

| 项目 | 当前限制 |
| --- | --- |
| 单个上传文件 | 最大 10 MB |
| Word 批量生成 | 每批最多 500 条记录 |
| 名单转表格 | 最多 5000 个姓名，最多 50 列 |
| 数据保存 | 不持久化；刷新/关闭页面会清空输入 |

浏览器下载站点资源时仍会访问托管平台；用户选取的文档和输入的数据不发送到服务器。没有账号、云端同步或历史记录功能。建议使用较新的桌面版 Chrome/Edge/Firefox；大批次导出耗时取决于设备内存和文档复杂度。

## 本地开发

要求 **Node.js 22.13 或更高的 Node.js 22 版本**及 npm。

下载并解压项目，或克隆自己的仓库后进入项目目录：

```bash
npm ci
npm run dev
```

访问终端显示的本地地址。可直接修改 `app/page.tsx`、`app/general-template.tsx` 与 `app/globals.css`。

```bash
npm run build    # 生成 dist/ 静态文件（样式测试需要构建产物）
npm test         # 文本解析、模板填充、文档生成和样式测试
npm run preview  # 本地检查生产构建
```

不用设置环境变量，也不用配置数据库。此开源发行版通过 Vite 挂载同一套 React 页面，不包含原托管环境的项目标识、认证代码和服务器配置。

## 部署到 GitHub Pages

本项目的全部业务逻辑运行在浏览器中，因此可以部署到 GitHub Pages。仓库已包含 `.github/workflows/pages.yml` 自动部署流程。

1. 在 GitHub 创建公开仓库（建议名称 `wenban-office`），将本项目推送到 `main` 分支。
2. 打开 **Settings → Pages**，将 **Build and deployment → Source** 设置为 **GitHub Actions**。
3. 如果工作流未自动运行，进入 **Actions → Deploy GitHub Pages → Run workflow** 手动触发。
4. 工作流将安装锁定依赖、构建静态文件、执行测试并部署 `dist/`。
5. 等待 `build` 和 `deploy` 两个任务成功，在 **Settings → Pages** 打开访问链接，并更新本 README 的「在线访问」。
6. 后续每次推送到 `main` 自动重新部署。Fork 后也需在自己的仓库启用 Pages/Actions。

工作流使用 GitHub 自带的 `GITHUB_TOKEN` 和 OIDC 权限，无需在仓库添加个人访问令牌。部署任务权限为 `pages: write` 和 `id-token: write`；构建任务仅有代码读取权限。

`vite.config.ts` 使用 `base: './'`，生成相对资源路径，兼容 `用户名.github.io/仓库名/` 和自定义域名。应用只有一个入口页，工具切换不依赖服务器路由。

参考：[GitHub Pages 自定义工作流](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)、[Vite 静态部署](https://vite.dev/guide/static-deploy.html)。

## 其他静态托管

运行 `npm ci && npm run build` 后，将 `dist/` 的内容上传到任意支持 HTTPS 的静态服务器（例如 Nginx 或 Cloudflare Pages）。构建命令为 `npm run build`，输出目录为 `dist`。无需 Node.js 常驻服务器。不要通过双击本地 HTML 文件的方式运行生产页面，请通过 HTTP/HTTPS 提供服务。

## 项目结构与技术栈

| 路径 | 用途 |
| --- | --- |
| `main.tsx` / `index.html` | 静态应用入口与页面元信息 |
| `app/page.tsx` | 工作台、奖状、桌签、名单转表格 |
| `app/general-template.tsx` | 通用模板多字段填充界面 |
| `app/globals.css` | 工作台样式与响应式布局 |
| `lib/documents.mjs` | Word 模板检查、渲染、合并、下载 |

## 常见问题

**部署后页面空白？**
检查 Actions 是否成功、Pages 来源是否为 GitHub Actions，并确认上传的是 `dist/`。资源路径应保持当前相对路径配置。

**模板无法填充？**
检查格式是否为 DOCX、是否使用单层花括号、占位符是否闭合，以及所有字段是否匹配。加密或损坏的文件需先在 Office 中修复/另存。

**桌签上方文字方向或字体不对？**
先用 Microsoft Word/WPS 打开结果，确认字体安装情况；艺术字兼容性因软件而异。可上传在目标软件中制作并验证过的自定义模板。

**为什么缺少合并导出选项？**
检测到多节或页眉页脚变量时仅提供 ZIP，保留每份文档的独立页面结构。

**下载慢或页面暂时无响应？**
压缩及文档渲染在本机执行。减小模板中的图片，或将名单拆成较小批次。
